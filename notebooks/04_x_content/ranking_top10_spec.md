# ランキング TOP10 画像生成 — 仕様書

対象ノートブック（新規作成予定）: `notebooks/04_x_content/ranking_top10_image.ipynb`
ベース設計: `XXクイズ回答発表.ipynb` セル3（インチ基準レイアウト + 動的カード高さ + 16:9クロップ）
参照データ: `202608_sixfonia_ranking_quiz.tsv`

---

## 1. 目的

TSV で受け取った動画一覧を、指定プレイリストで絞り込んだうえで再生数の伸び TOP10 として集計し、
X（旧Twitter）投稿用の1枚のPNG画像として出力する。
デザインモチーフは**五線譜**（白背景に横黒線）。カードが五線譜の上に並ぶ見た目にする。

## 2. 出力

| 項目 | 値 |
|---|---|
| 形式 | PNG（RGB、白背景） |
| 幅 | 9.0 inch |
| 高さ | 内容から自動算出（TOP10・全カード2行なら約 14.3 inch） |
| DPI | 260（定数 `OUT_DPI`） |
| 想定ピクセル | 約 2340 × 3700 px |
| ファイル名 | `ranking_top10_{プレイリスト名}.png`（空白・記号は `_` に置換）<br>例: `ranking_top10_シクフォニ歌チャレンジ.png`<br>`top10` は**固定表記**。`TOP_N` を変えても件数が少なくてもファイル名は変わらない（別名にしたい場合は `OUT_PATH` で明示指定する） |

> 既存コードは系統違いのファイル名（`1year_ago_videos.png`）を使い回し、プレイリストを変えても同名で上書きされる状態だった。本仕様ではプレイリスト名を含めて衝突を避ける。

## 3. 入力データ（TSV）

### 3.1 ファイル仕様

| 項目 | 値 |
|---|---|
| 区切り | タブ (`\t`) |
| ヘッダー | 1行目にあり |
| 文字コード | UTF-8（BOMなしを確認済み。`encoding="utf-8-sig"` で読む＝BOM有無どちらも可） |
| クォート | **なし**。`title` に生の `"` が含まれる行が4件ある（例: `【密着】メンバーに24時間"彼女風LINE"を...`）ため、`quoting=csv.QUOTE_NONE` で読み込む |
| 改行 | CRLF |
| 行数 | 278データ行（サンプル） |
| ソート | `view_diff` 降順で既にソート済み。**コード側でも明示的にソートし直す**（前提に依存しない） |

### 3.2 列と用途

| # | 列名 | 例 | 本ツールでの用途 |
|---|---|---|---|
| 1 | `thumbnail_url` | `https://img.youtube.com/vi/uC_Q65NHb90/maxresdefault.jpg` | **サムネ取得の第1候補URL** |
| 2 | `videoid` | `uC_Q65NHb90` | サムネ取得のフォールバックURL組み立て／重複検知 |
| 3 | `title` | `シクフォニ - しっくす。 [Official Music Video]` | **カードのタイトル** |
| 4 | `publish_date` | `2023-06-04` | **タイトル末尾に `（2023.06.04）` として連結** |
| 5 | `from_view_date` | `20251231` | サブタイトルの自動生成 |
| 6 | `from_view_count` | `2530393` | 未使用 |
| 7 | `to_view_date` | `20260805` | サブタイトルの自動生成 |
| 8 | `to_view_count` | `2698559` | 未使用 |
| 9 | `view_diff` | `168166` | **ランキングのソートキー（降順）**。int にキャスト |
| 10 | `playlist_name` | `シクフォニオリジナル曲` | **絞り込みキー（必須指定）** |

### 3.3 絞り込みと集計

```python
TSV_PATH        = "202608_sixfonia_ranking_quiz.tsv"
FILTER_PLAYLIST = "シクフォニ歌チャレンジ"   # ★必ず指定する
TOP_N           = 10
```

処理順序：

0. 必須列の存在を検査する。1つでも欠けていたら、欠けた列名と実際に読めた列名を並べて `ValueError`
   （タブ区切りでない＝CSV で保存された場合、列が1つしか読めないのでここで気づける）
   - 必須列: `thumbnail_url` / `videoid` / `title` / `publish_date` / `from_view_date` / `to_view_date` / `view_diff` / `playlist_name`
1. TSV を読み込む（`view_diff` を int 化）
2. `playlist_name == FILTER_PLAYLIST` で絞り込む
3. `view_diff` 降順にソート（`kind="stable"`。同値のとき TSV の並び順を保ち、実行ごとに順位が入れ替わらないようにする）
4. 先頭 `TOP_N` 件を取得（件数が `TOP_N` 未満なら**あるだけ**使う）
5. 上から 1位, 2位, … と採番

**ガード（実行時チェック）**:

| 状況 | 動作 |
|---|---|
| `FILTER_PLAYLIST` が `None` / 空文字 | `ValueError` で停止（重複行が混ざるため必ず指定させる） |
| 該当プレイリストが0件 | `ValueError` で停止。TSV内に存在する `playlist_name` の一覧をエラーメッセージに出す |
| 絞り込み後に `videoid` の重複あり | **警告を print**して `videoid` の先頭行を残す（本来ユニークのはずなのでデータ異常の検知用） |
| 該当件数が `TOP_N` 未満 | 警告を print して、あるだけで画像を生成 |

## 3.5 クイズ用マスク

指定した順位のカード内容を隠して**クイズ版**の画像を作る。**1画像につき隠せるのは1順位**。

```python
MASK_RANK     = None      # 隠す順位。None なら回答発表版
MASK_STYLE    = "mosaic"  # "mosaic"（モザイク）/ "black"（黒塗り）
MASK_TARGET   = "both"    # "both" / "thumbnail" / "title"
MASK_MARK     = "？"      # 隠した場所に重ねる文字。"" なら描かない
MOSAIC_BLOCKS = 14        # モザイクの粗さ（横方向の分割数。小さいほど粗い）
```

### 隠すもの・隠さないもの

| 要素 | マスク時 |
|---|---|
| **順位数字** | **隠さない**。これがクイズの設問になる |
| サムネイル | `MASK_STYLE` に従いモザイク化 or 黒塗り。中央に `MASK_MARK` を重ねる |
| タイトル | 折り返し後の行数ぶんの高さの**帯**で覆う（黒 or グレー）。中央に `MASK_MARK` を重ねる |
| カード枠・区切り線・五線譜 | 隠さない |

タイトルは文字なのでモザイク化できない。`MASK_STYLE="mosaic"` のときは
グレー帯（`MASK_BAR_GRAY`）、`"black"` のときは黒帯で覆う。

### 実装上の要点

- **モザイクは `interpolation="nearest"` で描く。** `"lanczos"` のままだとブロックが
  平滑化されて元の絵が復元されてしまい、マスクとして機能しない
- `pixelate()` は「blocks 個まで縮小 → 最近傍で元サイズへ拡大」。元画像の解像度に
  関係なく見た目のブロック数が一定になる
- `MASK_MARK` の「？」には `path_effects.withStroke` で黒縁を付ける。モザイクの上でも読める
- **カード高さの計算はマスクの有無に依存しない**（折り返し行数から決まる）。
  そのためクイズ版と回答版でレイアウトが完全に一致し、切り替え投稿に使える

### 検証（`validate_mask()`）

| 状況 | 動作 |
|---|---|
| `MASK_RANK` が範囲外 | `ValueError`（指定可能な範囲を表示） |
| `MASK_STYLE` / `MASK_TARGET` が不正な値 | `ValueError`（取り得る値を表示） |
| 正常 | 隠す順位・方式・対象と、隠した動画のタイトルを `print`（何を隠したか確認できる） |

### 画像内のクイズ行

「設問文は本文、最低限の文脈だけ画像」という方針に基づき、
サブタイトルの下に1行だけ `QUIZ_NOTE_FMT`（既定 `"Q. {rank}位に入るのはどの動画？"`）を描く。
スクショ・転載されても「何を当てるのか」が伝わるようにするのが目的。

**この行の高さは回答版でも常に確保する**（テキストだけ描かない）。
そうしないとクイズ版と回答版で図の高さが変わり、切り替え投稿で画像がずれるため。
`QUIZ_NOTE_FMT = ""` にすると行ごと廃止され、高さも確保しない。

### 出力ファイル名

| `mask_rank` | ファイル名 |
|---|---|
| `2` | `ranking_top10_{プレイリスト名}_quiz2.png` |
| `None` | `ranking_top10_{プレイリスト名}_answer.png` |

## 3.6 一括生成と ZIP

`playlist_name` のパターンを TSV から全抽出し、プレイリストごとに画像を作る。

### 対象の決定

| 設定 | 既定 | 意味 |
|---|---|---|
| `ONLY_PLAYLISTS` | `None` | `None` なら全パターン。リスト指定でその名前だけ（試作用） |
| `MIN_POOL` | `10` | 母集団がこの本数未満のプレイリストはスキップ |
| `INCLUDE_EMPTY_PLAYLIST` | `False` | `playlist_name` が空欄の行を対象にするか |

読み込みセルが対象／スキップの一覧を表示し、生成前に総枚数が分かるようにする。

### 1プレイリストあたりの生成物

| 設定 | 既定 | 意味 |
|---|---|---|
| `MASK_RANKS` | `[2, 4, 9]` | クイズ版を作る順位 |
| `MAKE_ANSWER` | `True` | マスクなしの回答版も作るか |

母集団が足りず存在しない順位（例: 掲載8件で9位）はスキップして続行する。

### ZIP

- `OUT_DIR`（既定 `ranking_images/`）に保存 → `ZIP_PATH`（既定 `ranking_images.zip`）へ
- **圧縮方式は `ZIP_STORED`（無圧縮）**。PNG は内部で既に DEFLATE 済みなので再圧縮しても縮まず、時間だけかかる
- `answer_key.txt` を同梱（下記）
- Colab なら `google.colab.files.download()` で自動ダウンロード。それ以外の環境では絶対パスを表示するだけ
- ZIP が 100MB を超えたら、`OUT_DPI` を下げた場合の推定サイズを添えて警告する

### `answer_key.txt`

3部構成。当日の作業をこのファイル1つで完結させるのが目的。

**1. クイズの答え**

```
■ シクフォニの日常（母集団 101本 / 掲載 10件）
    2位: b1N6-qB3xhg  【期待の新人】一人六役でグループ結成したらコスパよくね？？（2023.03.28）
    4位: ...
```

**2. ツイート下書き**

`QUIZ_PLAN`（セル ①-2）に定義した出題計画へ、実データを埋め込んだ本文を出力する。
当日はこのファイルからコピペするだけで投稿できる状態にするのが目的。

```python
QUIZ_PLAN = [
    {"q": 1, "playlist": "シクフォニの日常", "rank": 2, "post_at": "8/12 4:00",
     "quiz": "…{playlist}…{rank}位…", "answer": "…{title}…{views}…"},
    ...
]
```

| プレースホルダ | 中身 | 例 |
|---|---|---|
| `{q}` / `{rank}` / `{post_at}` | `QUIZ_PLAN` の指定値 | `1` / `2` / `8/12 4:00` |
| `{playlist}` / `{pool}` / `{pub_from}` / `{pub_to}` / `{from_date}` / `{to_date}` | `select_ranking()` の meta | `シクフォニの日常` / `101` |
| `{title}` | 正解の動画タイトル（**生タイトル**） | `【期待の新人】一人六役で…` |
| `{pub}` | 正解動画の投稿日 | `2023.03.28` |
| `{views}` | 集計期間の再生増加数を丸めた表現 | `約6.9万回` |
| `{age}` | 投稿日→集計終了日の経過年数 | `3年以上前` |
| `{answer_at}` | `ANSWER_AT` | `8/24 9:42` |

出力される各ブロックには**添付すべき画像のファイル名**と**X換算の文字数**が付く。

- 文字数は `x_length()` の概算（半角=1 / それ以外=2）。上限 `X_LIMIT = 280`（＝全角140字）
- 超過した本文には `← 上限超過！要短縮` を付け、実行ログにも本数を警告する
- `QUIZ_PLAN` の `playlist` が生成対象になければ、対象一覧を添えて `[!]` 行を出す（例外にはしない）
- 指定順位が存在しなければ同様に `[!]` 行を出してスキップ

固定文（回答スレッドの親・締め・導線用の返信）は `ANSWER_HEAD_TWEET` /
`ANSWER_TAIL_TWEET` / `ANSWER_LINK_REPLY` で定義する。

**3. 動画ID一覧（末尾）**

用途は**スプレッドシートに貼り付けて、別シートの再生データを `videoid` で絞り込む**こと。
そのため**タブ区切り**にする（貼り付けるだけで2列に分かれる）。

```
======================================================================
動画ID一覧（スプレッドシート貼り付け用・タブ区切り / 58本）
下のヘッダー行から最後までを選択してコピー＆貼り付けしてください
title は TSV のままのタイトルです（画像用に付けた投稿日は含みません）
======================================================================
videoid	title
1qf8424zjHM	【いれいす】推しがブチ切れる3分ちょいｗｗｗｗｗｗ【シクフォニ】【どこまでも怒れ】
ohrT3O44Owk	【期待の新人】一人六役でグループ結成したらコスパよくね？？
...
```

| 決めごと | 内容 | 理由 |
|---|---|---|
| 対象 | **画像に載った全動画**（各プレイリストの上位N件） | マスクした3本だけでは再生データの絞り込みに足りない |
| 重複 | `videoid` で排除、**初出のみ**残す | 同一動画が複数プレイリストのTOP10に入り得る |
| 並び | プレイリスト順 → 順位順（`dict` の挿入順） | 実行ごとに並びが変わらない |
| `title` | **TSV のままの生タイトル**（`raw_title`） | 画像用に連結した `（2023.06.04）` が付くと再生データ側と文字列一致しない |
| 区切り | タブ | スプレッドシートに貼るだけで列に分かれる。TSV 由来なのでタイトルにタブは含まれない |

このために `build_items()` が `title`（描画用・日付付き）と `raw_title`（TSV のまま）の
両方を持つようにしてある。

## 3.7 マスク候補の比較シート（セル ⑦）

「どのプレイリストで何位を隠すか」を決めるための一覧画像。出題本番用ではなく**選定用**。

- **行 = `COMPARE_PLAYLISTS`（4件）／ 列 = `COMPARE_RANKS`（2位・4位・9位）**
- 各マスに、そこを伏せた場合に隠れる動画の **サムネイル・順位・再生増加数・タイトル**を並べる
- タイトルは `CMP_TITLE_LINES`（既定3行）で切り、あふれたら末尾を `…` にする（`wrap_clip()`）
- 出力は `mask_candidates.png`。**ZIPには含めない**（本番の成果物ではないため）

配色・五線譜のヘッダーは本番画像と共通。列幅は
`(FIG_W - 左右マージン - 列間×(列数-1)) / 列数` で、サムネはその幅の16:9。
図の高さは行数から自動算出する。

この画像を見て割り当て（**4位×2 / 9位×1 / 2位×1**）を決め、
セル ①-2 の `QUIZ_PLAN` に反映してからセル ⑥ を再実行する。

### メモリ

図は保存のたびに `plt.close(fig)` する。数十枚を連続生成するため、閉じないと Colab のメモリを圧迫する。
サムネイルは `video_id` 単位でキャッシュされるので、同一プレイリストの4枚で再ダウンロードは発生しない。

## 4. 構成要素

```
┌──────────────────────────────────────────────┐
│                  ① タイトル                    │  ← 中央揃え・太字
│                 ② サブタイトル                  │  ← 中央揃え・細字グレー
│  ═════════════ 五線譜（区切り）═════════════   │
│ ┌────┬──────┬───────────────────────────┐ │
│ │ 1  │ サムネ │ 動画タイトル（2023.06.04）    │ │  ← ③ カード ×10
│ └────┴──────┴───────────────────────────┘ │
│ ┌────┬──────┬───────────────────────────┐ │
│ │ 2  │ サムネ │ 動画タイトル（2022.09.02）    │ │
│ └────┴──────┴───────────────────────────┘ │
│                    （…10位まで）                │
└──────────────────────────────────────────────┘
       ↑ 背景に五線譜（全幅の横黒線）が敷かれる
```

### ①② タイトル / サブタイトル

どちらも**プレースホルダ付きのフォーマット文字列**（`HEADER_TITLE_FMT` / `HEADER_SUB_FMT`）で指定する。

| プレースホルダ | 値 | 例 |
|---|---|---|
| `{playlist}` | `FILTER_PLAYLIST` | `シクフォニの日常` |
| `{pub_from}` / `{pub_to}` | 母集団の投稿年月レンジ | `2022.08` / `2023.08` |
| `{from_date}` / `{to_date}` | 再生数の集計期間 | `2025/12/31` / `2026/08/08` |
| `{pool}` | 絞り込み後の母集団の本数 | `101` |
| `{n}` | 実際に載る件数 | `10` |

- `{pub_from}` / `{pub_to}` / `{pool}` は**上位N件ではなく絞り込み後の全件**から算出する（サブタイトルは母集団を説明するものなので）
- `{from_date}` / `{to_date}` は `20251231` → `2025/12/31` に整形。全行同一である前提で先頭行を使い、混在時は警告を print
- 未定義のプレースホルダを書くと、使える名前を列挙した `ValueError` で止まる

| 項目 | タイトル | サブタイトル |
|---|---|---|
| 既定フォントサイズ | `HEADER_TITLE_FS` = 22 / bold / `#111111` | `HEADER_SUB_FS` = 13 / `#5a5a5a` |
| 自動縮小の下限 | `HEADER_TITLE_MIN_FS` = 15 | `HEADER_SUB_MIN_FS` = 10 |
| 配置 | 図幅中央 | 図幅中央 |

#### 複数行と自動縮小

`\n` で改行できる。`fit_fontsize()` が**いちばん長い行**の推定幅を測り、
カード幅（`FIG_W - LEFT_MARGIN - RIGHT_MARGIN` = 7.8 inch）に収まらなければフォントサイズを下げる
（下限 `HEADER_TITLE_MIN_FS` / `HEADER_SUB_MIN_FS`）。

**1行あたりの目安**: 22pt なら**全角25文字**（`7.8 ÷ (22/72) ≈ 25.5`）。
プレイリスト名（`シクフォニ歌ってみた合唱・コラボ` = 15文字）を差し込むと1行では足りないことが多いので、
**タイトルは2行構成を前提にする**。

#### ヘッダー高さの自動算出

固定値 `HEADER_H` は廃止し、行数とフォントサイズから積み上げて計算する。

```
header_h = HEADER_TOP_PAD          (0.12)
         + タイトル行数 × title_fs × HEADER_TITLE_LH / 72
         + HEADER_GAP              (0.16)
         + サブタイトル行数 × sub_fs × HEADER_SUB_LH / 72
         + HEADER_RULE_GAP         (0.24)
         + STAFF_GAP × 4           (五線譜1組の高さ)
         + HEADER_BOTTOM_PAD       (0.22)
```

タイトルを何行にしても、五線譜と1枚目のカードの間隔は一定に保たれる。

### ③ メイン（ランキングカード ×N）

1カード内の左→右の並び：**順位数字 → 区切り縦線 → サムネイル → 動画タイトル**

| 要素 | 仕様 |
|---|---|
| 枠 | `FancyBboxPatch` / 角丸 / 白塗り `#ffffff` / 黒枠 `#000000` linewidth 1.6 |
| 順位数字 | 1〜3位: fontsize 26・色 `#111111`／4位以降: fontsize 22・色 `#333333`。カード左端から `RANK_W` の領域に中央揃え。2桁以上は 0.82 倍に縮めて `RANK_W` からはみ出さないようにする |
| 区切り縦線 | 順位とサムネの間。黒・linewidth 0.9・alpha 0.5・カード上下から少し内側 |
| サムネイル | 16:9。カード基本高さから `THUMB_PAD` を引いた高さで固定。カードが縦に伸びても大きさは一定、縦センタリング |
| 動画タイトル | fontsize 13・色 `#111111`・左揃え・縦センタリング。カード右端手前で自動折り返し |

## 5. タイトル文字列の組み立て

```python
DATE_FORMAT = "（{y}.{m}.{d}）"   # → （2023.06.04）

display_title = row["title"] + format_publish_date(row["publish_date"])
```

- `publish_date` を `（YYYY.MM.DD）` に整形して**タイトル末尾に連結**する。
- 連結後の文字列を折り返し処理にかけるため、日付が行頭に回り込むことはあり得る（許容）。
- `publish_date` が空・解釈不能な場合は日付を付けずタイトルのみ。

### 5.1 受け付ける日付形式（Excel 対策）★重要

TSV を Excel で開くと `publish_date` は日付型に自動変換され、**保存し直すと `2023-05-12` が `5/12/2023` に化ける**。
`YYYY-MM-DD` だけを受け付ける実装だと、この場合に**全件の投稿日が黙って消える**。そのため複数形式を受け付ける。

| 入力 | 解釈 | 備考 |
|---|---|---|
| `2023-05-12` | 2023.05.12 | 正規の形式 |
| `2023/05/12` | 2023.05.12 | 年が先頭なので曖昧さなし |
| `20230512` | 2023.05.12 | 同上 |
| `5/12/2023` | 2023.05.12 | **曖昧**。定数 `SLASH_DATE_ORDER`（既定 `"MDY"`）で解釈。日月年環境なら `"DMY"` に変更 |
| 空文字・その他 | 日付なし | タイトルのみ描画 |

さらに `check_publish_dates()` で読み込み直後に検査し、

- 解釈できない行があれば件数と実例を警告
- `YYYY-MM-DD` 以外の形式が混ざっていれば件数・実例・採用した解釈順を警告し、「Excel で保存し直すと形式が変わる」旨を表示

**silent failure を作らない**のがこの検査の目的。

## 6. テキスト折り返し

セル3の `wrap_jp()` / `_tokenize()` / `_char_units()` を流用し、**1点拡張する**。

### 6.1 既存仕様（流用）
- 全角=1.0、半角≒0.55 で幅を近似
  - **既知の誤差**: 大文字の連続（例 `SHALL WE GONG`）は実幅が 0.55em より広く、折り返し位置が右にずれる。`CARD_RIGHT_PAD` = 0.22 inch の余裕で吸収する想定だが、はみ出しを完全に防ぐ保証はない。matplotlib で実測しない限り解消できないため、近似のまま運用する
  - East Asian Width の `A`（Ambiguous、`…` など）は全角扱い
- `#` / `@` で始まる語は次の空白までを1トークン扱い（日本語ハッシュタグを途中で割らない）
- 英数字と `_-.'` の連なりも1トークン扱い
- 1行に収まらない長トークンのみ1文字ずつ分割
- 折り返し行数からカード高さを決定: `card_h = max(CARD_H, n_lines * line_h + 2 * TEXT_VPAD)`

### 6.2 追加仕様：括弧ブロックを1トークンにする ★新規

実データで折り返しを検証したところ、`【】` が行をまたいで割れる問題が確認できた。

```
（既存ロジック）
  【爆笑】演技力KING面接したらキャラが濃すぎたｗｗｗｗｗｗ【シ
  クフォニ】【歌ってみた】（2022.08.20）        ← 「【シ / クフォニ】」で分断

  【English】Eigo dakede KING wo SING.【Saikyo】【SIXFONIA
  】（2023.08.09）                              ← 「】」だけが行頭に落ちる
```

対策として、`_tokenize()` に**対応の取れた括弧ブロックを1トークンとして扱う**規則を追加する。

- 対象括弧ペア: `【】` `『』` `「」` `（）` `《》` `［］`
- 開き括弧を見つけたら対応する閉じ括弧までを1トークンとする（ネストは考慮しない／最初に見つかった閉じ括弧まで）
- 閉じ括弧が見つからない場合は通常の1文字トークンとして扱う（フォールバック）
- ブロック単体が1行幅を超える場合のみ、既存ロジックどおり内部を1文字ずつ分割する

```
（拡張後）
  【爆笑】演技力KING面接したらキャラが濃すぎたｗｗｗｗｗｗ
  【シクフォニ】【歌ってみた】（2022.08.20）

  【English】Eigo dakede KING wo SING.【Saikyo】
  【SIXFONIA】（2023.08.09）
```

日本語の動画タイトルは `【】` 区切りが構造的な意味を持つため、この単位で改行するほうが可読性が高い。
日付の `（2023.06.04）` も自動的にこの規則の対象になり、途中で割れなくなる。

## 7. サムネイル取得

セル3の `load_thumb()` をベースに、**TSVの `thumbnail_url` を第1候補にする**よう変更。

1. `thumbnail_url` 列の値をそのまま HTTP GET（timeout 10秒）
2. 失敗したら `videoid` から組み立てた
   `maxresdefault.jpg` → `sddefault.jpg` → `hqdefault.jpg` → `mqdefault.jpg` の順にフォールバック
3. HTTP 200 かつ幅 120px 以上のものを採用（取得失敗時の小さなプレースホルダを除外）
4. `_crop_16x9()` で中央基準クロップ（4:3サムネの上下黒帯を除去）
5. 縮小はせず最大解像度のまま `imshow(interpolation="lanczos")` に渡す
6. 全滅時は単色ダミー画像を返し、処理は止めない（例外は握りつぶして次の候補へ）
7. 取得成功分は `video_id` をキーにメモリキャッシュし、セル再実行時に再ダウンロードしない

> TSVの `thumbnail_url` は全行 `maxresdefault.jpg` だが、`maxresdefault` は動画によっては存在しない（404）。フォールバック経路は必須。
> なお現行データでは `thumbnail_url` の値がフォールバック1番目と同一のため、第1候補として使う効果は実質ない（URL は重複除去される）。列の値が将来変わっても追従できるようにするための実装。

> **Shorts のサムネイル**は 16:9 の中に縦動画が収まった形（左右に黒帯）で返る。`_crop_16x9()` は 16:9 化のみを行い、この黒帯は除去しない（YouTube 側の仕様）。

## 8. レイアウト定数（inch）

| 定数 | 値 | 意味 |
|---|---|---|
| `FIG_W` | 9.0 | 図の横幅 |
| `LEFT_MARGIN` / `RIGHT_MARGIN` | 0.60 | 左右マージン（五線譜が覗く幅） |
| `TOP_MARGIN` | 0.30 | 上マージン |
| `BOT_MARGIN` | 0.40 | 下マージン |
| `HEADER_H` | 1.30 | タイトル+サブタイトル+五線譜区切りの領域 |
| `CARD_H` | 1.04 | カード基本高さ（行数が多いと自動で伸びる） |
| `ROW_GAP` | 0.18 | カード間の余白 |
| `RANK_W` | 0.92 | 順位数字の領域幅（カード左端から） |
| `THUMB_PAD` | 0.14 | カード上下からサムネまでの余白 |
| `THUMB_INSET` | 0.16 | 区切り縦線からサムネ左端までの余白 |
| `TITLE_GAP` | 0.16 | サムネ右端からタイトル文字までの余白 |
| `TITLE_FS` | 13 | タイトル文字サイズ（pt） |
| `CARD_RIGHT_PAD` | 0.22 | カード右端から折り返し位置までの余白 |
| `LINE_SPACING` | 1.2 | 折り返し時の行間 |
| `TEXT_VPAD` | 0.12 | カード上下からタイトル文字までの最低余白 |
| `DIV_INSET` | 0.16 | 区切り縦線をカード上下から内側に詰める量 |
| `CARD_LW` | 1.6 | カード枠の線幅 |
| `HEADER_TITLE_FS` | 22 | タイトル文字サイズ（pt） |
| `HEADER_SUB_FS` | 13 | サブタイトル文字サイズ（pt） |
| `RANK_FS_TOP3` | 26 | 1〜3位の順位数字（pt） |
| `RANK_FS_OTHER` | 22 | 4位以降の順位数字（pt） |
| `MASK_BLACK_FILL` | `#000000` | 黒塗りの色 |
| `MASK_BAR_GRAY` | `#9a9a9a` | モザイク時のタイトル帯の色 |
| `MASK_MARK_COLOR` / `MASK_MARK_STROKE` | `#ffffff` / `#000000` | 「？」の文字色・縁取り色 |
| `MASK_MARK_FS` / `MASK_BAR_MARK_FS` | 26 / 20 | サムネ上・タイトル帯上の「？」サイズ（pt） |
| `OUT_DPI` | 260 | 出力PNGの解像度 |

**座標系**: セル3と同じく、全定数をインチで定義 → 合計高さから `FIG_H` を算出 → `fx()`/`fyb()`/`fyc()` で figure 比率へ変換する方式。角丸の歪み防止に `mutation_aspect=FIG_H/FIG_W` を指定する。

タイトル折り返し幅の計算:
```
thumb_h      = CARD_H - 2 * THUMB_PAD                       # 0.76
thumb_w      = thumb_h * 16 / 9                             # 1.351
title_x_inch = LEFT_MARGIN + RANK_W + THUMB_INSET + thumb_w + TITLE_GAP   # 3.191
avail_inch   = (FIG_W - RIGHT_MARGIN - CARD_RIGHT_PAD) - title_x_inch     # 4.989
max_units    = avail_inch / (TITLE_FS / 72.0)               # ≒27.6 全角文字/行
line_h       = TITLE_FS * LINE_SPACING / 72.0               # 0.217 inch/行
```

カード高さと行数の関係（`CARD_H` = 1.04）:

| 行数 | 必要高さ | カード高さ |
|---:|---:|---|
| 1〜3行 | 0.46 〜 0.89 | `CARD_H` のまま（1.04） |
| 4行 | 1.11 | 1.11 に伸びる |
| 5行 | 1.32 | 1.32 に伸びる |

サンプルデータのタイトル（投稿日を連結した状態）は 38〜52 全角相当のため、**多くは2行**に収まる。

## 9. 五線譜（背景）

| 項目 | 値 |
|---|---|
| 本数 | 5本1組 |
| 線間 | `STAFF_GAP` = 0.045 inch |
| 線色 | `#000000` |
| 線幅 | 0.8 |
| 透明度 | `STAFF_ALPHA` = 0.30 |
| 描画範囲 | **図の全幅**（左右マージンの外まで。full-bleed） |
| 配置 | 各カード行の**垂直中心**に1組ずつ |
| 描画順 | カードより**下**（`zorder` を下げる） |

五線譜1組の高さは `STAFF_GAP × 4` = 0.18 inch で、カード高さ 1.04 inch の内側に完全に収まる。
カードは不透明白なので、**実際に線が見えるのは左右マージンの 0.60 inch ずつの帯だけ**になる
（カード間の余白には現れない）。カードが五線譜の上に乗った音符のように見えるのが狙い。

加えて、**ヘッダー直下の区切り**として五線譜を1組、alpha 0.9・カード幅と同じ範囲（左右マージン内）で描画する。
