# 推し活YouTubeツール — 概要仕様書

作成日: 2026-08-30
対象: 既存4アプリ（新着一覧 / 未視聴チェック / TOP9タイル画像 / ワードクラウド）の統合と是正
詳細仕様: 別紙（図解版）

---

## 1. 目的

### 解決する課題

| # | 課題 | 本質 |
|---|---|---|
| 1 | シクフォニはグループ＋個人で7チャンネルあり、供給が多くて追い切れない | **消費の可視化** — 何が出た？ 何をまだ見ていない？ |
| 2 | YouTube中心の推し活は、グッズやファンアートに比べて「こう推している」を伝える手段が少ない | **推し活のアウトプット化** — 視聴とコメントを見せられる形にする |

### 今回のゴール

4機能はすでに別々のアプリとして動いている。ゼロから作るのではなく、**共通のボトルネックを直して繋ぐ**のが本件のスコープ。

1. 4アプリが**共通の動画マスタ**を見るようにし、YouTube API のクォータ枯渇を解消する
2. ソースに直書きされた **API キーを止める**
3. TOP9画像アプリを**実データ（英語ロケールの Takeout）で動く**ようにする
4. ワードクラウドを「概要欄」から**「自分のコメント」入力**に作り替え、Colab から Streamlit へ移して他の人も使えるようにする

---

## 2. スコープ

| | 機能 | 解く課題 | 入力 | 出力 |
|---|---|---|---|---|
| **A** | 新着一覧（昨日 / 今週 / 今月） | 1 | なし | 期間別の動画リスト |
| **B** | 未視聴候補 / リピート推奨 | 1 | `watch-history.json` | 絞り込み可能な動画リスト |
| **C** | 視聴回数TOP9タイル画像 | 2 | `watch-history.json` | 3×3 の PNG |
| **D** | 自分のコメントのワードクラウド | 2 | `comments*.csv` | チャンネル別7枚＋全体1枚の PNG |

A・B が「見る」ため、C・D が「見せる」ためのツール。

**対象外**: 日次再生数の収集・ランキング分析（既存の `sixfonia_analytics` パッケージと Colab ノートブックが担当）。TSV を手で用意する `ranking_top10_image` 系の導線は本件では使わない。

## 4. 目標構成

```
[本リポジトリ] unofficial_sixfonia_analytics（非公開）
  └ GitHub Actions（毎日 JST 23:00）
      collect.fetch_video_master で7チャンネル分を取得
      → Vercelアプリの public/data/videos.json へ push

[Vercelアプリ]  アプリB を本体に、アプリA を統合
  /            A: 新着一覧（昨日/今週/今月）  入力不要・誰でも閲覧可
  /unwatched   B: 未視聴 / リピート    watch-history.json をアップロード

[Streamlitアプリ]  アプリC を本体に、D をタブ追加
  タブ1  C: 視聴TOP9タイル画像       watch-history.json をアップロード
  タブ2  D: コメントワードクラウド     comments*.csv をアップロード
```

4アプリ → **2アプリ + 1データソース**。どちらのアプリもブラウザから YouTube API を呼ばない。

## 5. 主要な決定事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | 動画マスタの取得 | 都度取得をやめ、**毎日夜1回のスナップショット**にする。`search.list`（100 units）を `playlistItems.list`（1 unit）へ置き換え、**700 units/表示 → 約200 units/日** にする |
| 2 | スナップショットの配置 | Vercelアプリの `public/data/videos.json`。公開URLになるので Streamlit 側からも同じものを読める |
| 3 | API キー | ローテートし、Vercel 環境変数と Actions secrets にのみ置く。クライアントには一切出さない |
| 4 | チャンネルの判定方法 | 視聴履歴の `subtitles` ではなく **`videoId` × 動画マスタの突合**。削除・非公開動画や YouTube Music 経由の再生も正しく拾えるため |
| 5 | 「未視聴」の定義 | **7チャンネルの全動画**を対象にし、履歴に無いものを未視聴候補とする。履歴の保存期間による不完全さは注記で明示する |
| 6 | 新着一覧の期間区分 | **昨日 / 今週 / 今月の3区分**。「今日」は作らない — 今日の動画は YouTube ですぐ見られるし、夜のバッチではその日の分をまだ取得できていないため |
| 7 | Shorts と長尺 | セクションは**分けない**。ただし未視聴一覧は本数が多くなるため、絞り込みトグルだけは持つ |
| 8 | TOP9画像 | 期間フィルタあり。**視聴回数の数字は画像に載せない** |
| 9 | ワードクラウドの単位 | **チャンネル別7枚＋全体1枚**。語数が少ないチャンネルは警告バッジを出す |
| 10 | ワードクラウドの語数しきい値 | 文字数ではなく**延べ語数**で判定する（サンプル生成で、文字数は足りても語数が足りない状態が確認されたため） |
| 11 | 形態素解析 | janome（純Python・依存なし）。Streamlit Cloud で確実に動く |
| 12 | チャンネル定義の単一化 | チャンネル名・表示名・テーマの対応はスナップショットの `channels` を唯一の正とする。`CHARACTER_MAPPING` や `CHANNEL_THEMES` に同じ情報を持たせない |
| 13 | アップロードファイルの扱い | Vercel 側（B）は**ブラウザ内だけで処理**しファイルは外に出ない。Streamlit 側（C・D）は**サーバーへ送られて**メモリ上で処理され、保存はしない。この差をアプリごとに正しく表示する |
| 14 | 公開範囲 | SNS投稿前提。自分のコメントなので自己責任で扱う |

## 7. 前提と制約

- **視聴履歴には視聴時間・完了率が入っていない。** あるのは再生開始のイベント列だけなので、「よく見ている」＝履歴への出現回数と定義する。
- **視聴履歴は Google 側の保存期間設定により古い分から削除される。** 実測したエクスポートは 2026-04-01 〜 2026-07-10 の 3.3ヶ月分しか含まなかった。未視聴判定は「履歴に残る範囲で未視聴」であり、この但し書きを画面に常時表示する。
- **Takeout は手動エクスポート。** B・C・D はエクスポート時点のデータを見る。再エクスポート手順への導線を置く。
- **コメント CSV の `Channel ID` は自分のチャンネル ID** であって、コメント先の動画のものではない。チャンネル判定は必ず `Video ID` 経由で行う。
- **Takeout のロケールは環境によって変わる。** 実測データは英語（`"Watched …"`）だった。日本語（`"… を視聴しました"`）と両方を受け付ける。
- アップロードされたファイルはメモリ上でのみ処理し、保存も外部送信もしない。

## 9. 未解決事項（着手前に決める）

| # | 論点 | 状況 |
|---|---|---|
| 1 | 機能D が当初の狙いに届くか | サンプル生成の結果、チャンネル別ワードクラウドの上位語は「このチャンネルの魅力」ではなく**そのとき見た動画の話題**（固有名詞・作品名）に寄った。「魅力を要約する」という当初の狙いに対して、手段を見直すか、狙いを「自分のコメントの記録」に読み替えるかの判断が要る |
| 2 | v0.dev の自動同期 | A・B は v0.dev から自動 push される構成。手編集に切り替えるなら自動同期を止める必要がある |
| 3 | スナップショットの push 認証 | Actions の既定 `GITHUB_TOKEN` は自リポジトリしか書けない。別リポジトリへ push するには fine-grained PAT か deploy key が要る |
| 4 | 「今月」バケットの縮退 | 月初が今週の中に入る週（例: 月初が水曜）は「今月」バケットが空になる。空表示にするか、隠すかを決める |
| 5 | 削除・非公開になった動画 | スナップショット再生成時に静かに消える。「見ようとしたらもう無い」を検知する仕組みは今回のスコープに入れていない |
